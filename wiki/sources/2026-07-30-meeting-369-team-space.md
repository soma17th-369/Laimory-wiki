# 369팀 스페이스 회의 - 2026-07-30

## 개요

알파 테스트에서 드러난 AI 관측성, 서버 간 인증, 데이터 수집 UX와 시간 처리 문제를 공유한 개발 회의다. Elasticsearch에 JSON 로그를 저장하는 방식은 운영 장애 추적에는 쓸 수 있지만 에이전트의 판단 이유와 중간 결과를 보기에는 한계가 있어, LLM 관측 도구인 Langfuse로 이동해 연결을 완료하고 실제 추적 테스트를 남겼다. AI 서버의 직접 DB 접근을 API 서버 경유로 바꾸는 작업도 PR 준비 단계였다.

모바일에서는 알림 전체 수집을 제거하고 사진 선택을 우선 사용자에게 맡겼다. 사진 자동 선택은 스케줄링과 제한 정책을 포함해 후속 논의하기로 했다. 서버 간 콜백 토큰은 작업 단계 검증을 포함하는 방식으로 구현했으나, 공개 구간에서 탈취될 위험까지 방어하려면 호출마다 토큰을 갱신하는 편이 낫다는 방향으로 의견이 모였다. 실제 사용 중 새벽 사진이 전날 타임라인에 포함되지 않는 하루 경계 문제와 UTC/KST 변환으로 점심이 저녁으로 해석되는 문제가 발견돼 다음 공동 작업에서 정책과 검증 절차를 다루기로 했다.

## 상세 요약

### AI 관측성을 Elasticsearch에서 Langfuse로 이동

- Elasticsearch에 JSON 로그를 저장하는 방식은 운영상 오류 추적에는 유용하지만, 에이전트 구조, 판단 이유, 중간 결과를 분석하는 데 한계가 있다고 판단했다. (`1:13–1:49`)
- 자동 전사에서 `랭피우스`로 기록된 Langfuse로 관측성을 옮겨 연결은 완료했으며, 실제 trace가 제대로 남는지 테스트가 필요했다. (`1:49–2:05`)
- AI 서버의 직접 DB 접근을 API 서버가 수행하도록 바꾸는 서버 변경을 올렸고, 이에 맞춘 AI 서버 PR을 준비 중이라고 보고됐다. (`2:07–2:21`)

### 알파 테스트와 AI 품질 개선

- 실제 테스트에서 알림이 전체 수집돼 과도한 데이터가 전송됐고 AI 서버가 처리 중 실패하는 문제가 있었다. 모바일 쪽은 전체 수집 옵션을 제거하고 최대량 제한이 필요하다는 점을 확인했다. (`2:25–4:28`, `6:32–11:48`)
- 품질 개선 항목은 이미 수집됐으나, 어떤 계산과 평가 기준을 사용할지는 다음 날 실제 로그를 함께 보며 논의하기로 했다. (`2:25–3:18`)
- AI 생성 결과의 부제목이 지나치게 길다는 사용성 피드백과 시간대 해석 오류가 추가됐다. (`27:24–28:54`)

### Grafana, 테스트 코드와 인프라 관리

- Grafana 가용 메모리 알림 임계값을 15%에서 10%로 낮추고, 에러·경고 로그에서 해당 시간대 로그 탐색 화면으로 바로 이동할 수 있도록 대시보드를 개선했다. (`4:44–5:33`)
- 테스트 커버리지를 확인하고 AI가 작성한 테스트 코드의 품질을 다시 AI에 평가시키는 접근을 시도했으나, 신뢰할 수 있는 검증 방식인지 의문이 남았다. (`5:35–6:03`)
- 실제 인프라를 수동으로 변경하면서 Terraform 상태와 계속 어긋나고 코딩 에이전트 사용량이 커져, Terraform 코드를 제거하는 변경을 진행 중이라고 보고됐다. (`6:03–6:26`)

### 사진 수집과 사용자 흐름

- 디버그용 인앱 DB에 사진을 주입하던 흐름 대신 일반 갤러리 선택 UI를 사용해, 당장은 사진 선택을 사용자에게 맡기기로 했다. (`7:14–8:27`)
- 사진 자동 수집은 WorkManager 등 스케줄링, 사진 개수 제한, 선택 알고리즘을 포함해 공동 설계가 필요하다고 봤다. (`8:27–9:08`)
