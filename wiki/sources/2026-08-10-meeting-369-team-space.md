# 369팀 스페이스 회의 요약 - 2026-08-10

## 개요

이번 회의는 AI 구독·API 비용 점검, 중간 발표 보고서의 구성, 사용자 data 비식별화와 민감정보 filtering, 개인정보 제3자 제공 및 국외 이전 동의 UX, 그리고 회고 기능을 목표·할 일 관리 기능으로 바꿀 가능성을 중심으로 진행되었다.

AI 도구 비용과 관련해서는 월 100달러 구독의 실제 사용률이 낮아 보인다는 문제의식과 구독료 외에 API 사용료가 별도로 발생한다는 점이 논의되었다. Claude와 GPT 계열 중 무엇을 줄일지는 실제 사용량을 더 확인한 뒤 판단하기로 했으며, 회의 중 제시된 “100달러로 1,000달러의 효과” 같은 값은 AI가 추산한 설명일 뿐 검증된 비용 절감 수치가 아니다. (`02:59-09:09`)

개인정보 보호 측면에서는 이메일·주민등록번호·여권번호·면허번호·카드번호·전화번호·계좌번호처럼 정규식으로 잡을 수 있는 값과 사람 이름·상세 주소·병원·종교·정치처럼 비정형이거나 맥락 의존적인 정보를 구분했다. 사용자와 AI 저장 data의 연결 관계를 끊거나 별도 저장소·mapping table을 사용하는 방안이 논의되었지만, 정확한 비식별화 구조와 비정형 민감정보 처리 방법은 아직 미결이다. (`14:35-20:09`)

동의 UX에서는 회원가입 동의와 타임라인 생성 시점의 제3자 제공·민감정보 처리·국외 이전 고지를 구분하고, 동의 시점과 승인 상태를 server에 저장할 필요가 있다는 해석이 공유되었다. 동의 이력용 별도 DB table을 만드는 방향이 제시되었으나, 약관 본문을 API로 내려줄지 Notion 같은 외부 문서로 제공할지는 정하지 않았다. (`20:14-25:14`)

제품 기능은 기존 회고 기능이 현재 수집 가능한 data와 MVP 구조로는 충분한 품질을 내기 어렵다는 문제를 다시 검토했다. 회고를 과감히 빼고 타임라인을 기반으로 한 목표·할 일 또는 challenge 기능을 구체화하자는 방향이 제안되었지만, 목표 검증 data와 기능 정의가 부족해 최종 명세로 확정되지는 않았다. (`28:13-35:05`)

## 상세 요약

### AI 비용과 evaluation

- 월 100달러 요금제의 주간 사용량이 20%를 넘는 경우를 거의 보지 못했다는 경험과 구독료·API 비용이 별도라는 확인이 공유되었다. 실제 사용량을 더 면밀히 확인하기로 했다. (`03:05-09:09`)
- 생성형 AI evaluation system을 계속 만들고 있으며, 더 정량적인 metric을 정해 논문이나 특허로 발전시킬 가능성까지 고려하고 있다. (`11:30-12:05`)
- Bedrock으로 옮길 수 있다는 의견이 있었고, MVP test 동안 기존 GPT-4 mini 기준을 유지할 수 있도록 현재 5달러 한도를 임시 상향하겠다고 했다. (`13:21-14:23`)
- APM 작업을 마쳤고 Grafana Explore의 `Tempo`로 trace를 확인할 수 있다고 보고했다. (`14:35-15:00`)

### 개인정보 filtering과 비식별화

- 정규식 탐지 대상으로 이메일, 주민등록번호, 여권번호, 면허번호, 카드번호, 전화번호, 계좌번호를 열거했다. (`15:00-15:33`)
- 사람 이름, 상세 주소, 병원·종교·정치 같은 맥락 정보는 정규식만으로 다루기 어렵고 별도 검토가 필요하다. (`15:34-19:09`)
- 사용자 ID와 AI item·user memory 사이 관계를 끊을 mapping table, 별도 AI 저장소, server-side mapping 관리 등을 검토했으나 결론을 내리지 못했다. (`16:42-18:40`)
- 전사상 `SSLM`으로 들리는 기술을 활용할 수 있다는 의견이 있었지만 정확한 명칭, 비용, 구현 가능성은 확인되지 않았다. (`19:30-20:09`)

### 동의와 약관 UX

- 제3자 제공·민감정보 처리 외에 외부 LLM API를 통한 개인정보 국외 이전 고지 또는 동의가 필요할 수 있다는 조사 결과가 공유되었다. 이는 법률 검토가 완료된 결론이 아니다. (`20:14-21:18`)
- 사용자가 언제 무엇에 동의했는지 server에 저장하고 별도 DB table을 두는 방향이 제시되었다. (`21:19-23:07`)
- app update 없이 약관을 변경할 수 있도록 Notion link, API text, image를 비교했으나 최종 전달 방식은 정하지 않았다. (`23:07-25:14`)
