# 369팀 스페이스 회의 요약 - 2026-08-25

## 개요

이번 회의에서는 AgentCore 배포 상태, production timezone 문제, mentor feedback 반영, Android timeline의 읽기·편집 UX, onboarding initializer API, Bedrock model region 제약, 알림 filter 검수 등을 논의했다. 회의의 가장 긴 구간은 AI가 만든 초안을 사용자가 편집한 뒤 저장하고, 저장된 timeline을 다시 읽거나 고치는 경험을 어떤 화면 구조로 제공할지 검토하는 데 쓰였다.

Android 쪽에서는 카드 중심 편집 화면이 완성된 기록을 읽기에는 지저분하다는 문제의식 아래, 선과 dot을 이용한 timeline형 읽기 화면을 제시했다. 글자 크기, 시간 표기, 사용자 메모의 강조, 사진 크기와 순서, AI 질문을 어디에 배치할지가 쟁점이었다. 최종적으로는 읽기 화면과 편집 화면을 분리하되, 두 화면의 시각적 간격을 줄이고 최근 생성 draft는 편집 가능한 상태로 보여주는 방향을 먼저 구현해 beta test에서 검증하기로 했다. (`05:14-45:12`, `50:17-54:37`)

초기 접속 시 user별 onboarding 여부, 약관 상태, 향후 알림 설정 등을 가져올 initializer endpoint를 만들기로 했다. onboarding은 최초 한 번 보여주고 설정에서 다시 볼 수 있게 하는 구상이었다. (`45:15-47:23`) 알림 filter는 여러 앱·keyword 조합을 이미 정리했지만 실제로 필요한 notification이 포함되는지 추가 검수가 필요하며, debug build에는 삭제하지 않는 한 365일 동안 수집 데이터가 유지된다고 설명되었다. (`01:01:43-01:07:16`)

## 상세 요약

### AgentCore, branch 운영, model 후보

- AgentCore 자체 배포는 되었고, application 연결과 end-to-end test를 마무리하는 단계라고 보고되었다. 예상보다 배포 요소가 많아 팸플릿과 품질 개선 작업은 뒤로 밀렸다. (`00:24-01:54`)
- 전사상 default branch와 production branch를 구분하고, development 내용을 main에 올릴 때 version patch를 수행하는 방식이 설명되었다. branch 이름은 자동 전사 오류로 불명확하므로 repository에서 확인해야 한다. (`01:04-01:30`)
- Bedrock playground에서 `GPT 5.6 Luna`로 들리는 모델을 봤다는 제보가 있었고, 가격이 기존 mini 모델보다 높을 수 있어 확인하기로 했다. (`01:56-04:19`)
- 회의 후반에는 해당 model이 Seoul region에서 제공되지 않고 미국 쪽 region에서만 가능해 보인다는 설명과, cross-region 호출 가능성을 다시 확인하자는 논의가 있었다. 최종 가능 여부는 확정되지 않았다. (`47:27-49:59`)

### production timezone과 backend feedback 반영

- 자정에 온 알림 문제는 notification 자체뿐 아니라 production timezone 설정이 꼬인 영향도 있었다고 보고되었고, 해당 문제와 mentor feedback을 함께 반영 중이며 거의 끝났다고 말했다. (`04:25-04:56`)
- endpoint 변경은 mobile에 반영되었고, 자동 데이터 수집에서 발견된 문제도 추가 수정했다고 보고되었다. (`05:08-05:35`)

### timeline 읽기 화면의 시각 구조

- 여러 timeline·diary app 사례를 참고해 기존 card 느낌을 줄이고 dot과 세로선을 활용한 읽기 화면을 시험했다. 구조는 대체로 긍정적으로 평가되었으나 title과 시간 글씨가 크고 사용자 메모가 상대적으로 작다는 feedback이 있었다. (`06:10-18:32`)
- 사진 중심 event와 글 중심 event의 image size 차이가 지나치게 커 보였고, blog 글처럼 사진 크기를 더 균일하게 배치하자는 의견이 나왔다. 사진과 설명의 순서는 기존 edit flow와의 일관성을 고려해 우선 현재 방식을 시험하기로 했다. (`17:07-23:33`)
- 24시간제 숫자만으로는 낮과 밤이 직관적이지 않고 분 단위가 지나치게 세밀해 보일 수 있어, 오전·오후 표기와 시간 단위를 조정하는 안을 검토했다. 정확한 표기 방식은 확정되지 않았다. (`19:43-22:07`)
- 저장된 기록에서 시작·종료 시간을 모두 보여줄지, 시작 시간만 보여줄지도 열린 문제로 남았다. (`12:06-12:40`)

### 읽기·편집 mode와 AI 질문

- AI 초안이 처음 나온 시점에는 사용자가 수정·메모·질문 응답을 해야 하므로 명백한 편집 affordance가 필요하고, 저장된 결과는 읽기에 집중해야 한다는 점에는 대체로 공감대가 있었다. (`26:35-42:46`)
- 기존 카드 편집 화면은 입력란과 질문을 자연스럽게 보여준다는 장점이 있지만, 완성된 결과와의 시각적 차이가 너무 크고 저장 후 읽기에는 지저분하다는 문제가 있었다. (`28:49-38:32`)
- 저장 뒤에도 AI 결과를 수정할 수 있어야 하지만, 과거 기록 수정 수요가 얼마나 큰지 불명확하므로 편집 UX를 지나치게 복잡하게 만들 필요는 없다는 의견이 나왔다. beta test에서 과거 기록 열람률과 수정률을 측정하자는 제안이 이어졌다. (`36:14-44:23`)
- 한 구상은 draft, saved-read, saved-edit의 세 상태를 두는 것이었지만 복잡성을 우려했다. 읽기 화면에서 연필이나 점 세 개 button으로 간단 편집을 진입시키고 두 화면의 typography를 비슷하게 맞추는 절충안이 논의되었다. (`50:17-54:37`)
- 구현 방향은 읽기와 편집을 분리하되, 현재 구조를 유지하면서 메모 입력 가능성을 더 명확히 하고 beta tester feedback으로 재평가하는 것이었다. 이것이 최종 UX 확정이라고 단정할 수는 없다. (`41:37-45:12`)

### onboarding initializer API

- user가 처음 가입했는지 확인해 onboarding을 한 번 보여주고, 다시 보고 싶을 때는 settings에서 접근할 수 있게 하는 흐름이 제안되었다. (`45:15-46:07`)
- 앱 시작 시 호출하는 initializer API가 onboarding 여부와 약관 상태, 향후 공지·알림 등 user별 초기 상태를 함께 반환하도록 만들기로 했다. (`46:11-47:23`)
- 전사에서는 `initializer endpoint`로 보이는 표현이 나오며, 정확한 endpoint 명칭과 response schema는 API 문서를 확인해야 한다.

### notification filter와 검수

- AI를 활용해 문자, 금융·결제, 배달·카페, 쇼핑·택배, 예약·문화, 이동·여행 등 category별 앱과 filter 후보를 database에 추가했다고 보고되었다. 임의 생성된 항목이 포함되어 실제 앱 package와 notification 형식을 확인해야 한다. (`01:01:43-01:02:23`)
- Naver 예약 notification처럼 동일 vendor 안에서도 app/package가 다를 수 있어, 실제로 filter가 걸리는지 debug data로 검수하기로 했다. (`01:02:23-01:04:58`)
- filter 생성 자체는 codebase 작업이고 app에서는 app·keyword 선택 정도만 할 수 있다고 설명되었다. 팀은 우선 기존 정책을 검수하고, 각자의 사용 pattern에서 timeline 생성에 도움 된 notification이 포함되는지 확인하기로 했다. (`01:03:43-01:06:36`)
- debug mode에서는 수집 데이터가 365일 유지되며, 사용자가 일부 데이터 삭제 기능을 누르지 않으면 과거 사례를 재생성 test에 쓸 수 있다고 설명되었다. (`01:06:40-01:07:16`)

### 경쟁 app 참고

- 여러 diary·timeline app의 읽기 화면, bottom sheet, map 연결, 위치·시간 자동 추출, bookmark 등을 참고했다. 일부 기능은 향후 확장 가능성으로만 언급되었고 현재 scope에 포함된 결정은 아니다. (`11:55-15:38`, `54:58-01:01:06`)
- map에서 event를 선택해 해당 순간을 overlay로 보여주는 사례와 Google Map이 예상보다 자연스럽게 보인다는 반응이 있었다. (`56:03-58:32`)

## 주의 사항

- 화자명은 전사에 있으나 실제 feature owner나 승인 권한은 별도 문서 없이 확정하지 않았다.
- `Luna`, `Nova Lite`, `AgentCore`, `initializer`, branch 이름과 여러 app 이름은 자동 전사 오류 가능성이 있다.
- UI 논의에는 시안과 화면 공유가 포함되어 있어 전사만으로 정확한 배치·크기·색상을 재현할 수 없다.
- region과 model 가격에 관한 내용은 회의 중 확인 단계였으며 공식 AWS 제공 범위를 검증한 결과가 아니다.
- 경쟁 app의 사용자 수와 평점에 관한 대화는 즉석 탐색이며 신뢰할 수 있는 시장조사로 취급하면 안 된다.
