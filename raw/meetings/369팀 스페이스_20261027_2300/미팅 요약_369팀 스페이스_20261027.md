미팅 요약

메모
개요
참석자: 전형선 (designer/engineer) 및 이동건 (product/lead reviewer), 김수현 및 기타 인원 참조. 회의는 튜토리얼 APK 및 갤러리 표시, 갤러리 상호작용 동작, 장소 선택 UI 디자인, AI 기반 장소 추천, 장소 대 주소의 데이터 세분화, 안전한 편집/삭제 처리 등을 다뤘습니다.
주요 결과: 디버그 빌드의 갤러리 프로토타입이 검증되었고 루핑 없는 경계형 횡스와이프와 명확한 종료 상태 애니메이션으로 업데이트할 예정입니다(담당: 전형선). 장소 선택에 대해서는 이벤트당 단일 장소 모델을 선호하며 제목에서 장소명을 제거하고 별도 위치 컴포넌트 또는 부제목을 사용하는 쪽으로 합의했습니다(이 입장은 이동건이 제안하고 전형선이 지지함). AI 동작은 장소 후보를 순위화하고 최상위 후보를 기본으로 제시하되 사용자가 재선택할 수 있도록 유지할 것입니다(이동건 요청). 이동 이벤트에는 주소 수준의 대략적 데이터 사용, 의미 있는 정지형 이벤트에는 명시적 장소명 유지로 결정했습니다.
안전성과 편집: 팀은 자유 텍스트 삭제 대신 명시적 컴포넌트 수준 삭제(X) 컨트롤을 선호하며 실수로 인한 데이터 손실을 방지하기 위해 확인 또는 되돌리기 흐름을 고려하기로 했습니다; 이동건은 편집 화면을 별도의 저장 버튼 없이 나가더라도 편집 내용이 유지되기를 강조했습니다.
다음 단계 및 약속: 전형선은 프로토타입과 애니메이션을 업데이트하고 장소-제목 트레이드오프를 테스트할 것입니다; 이동건은 AI 프롬프트를 조정하고 Discord를 통해 팀에 업데이트하며 후속 작업에 집중할 수 있음을 알렸습니다; 그룹은 일요일까지 미해결 설계 결정을 마무리하고 필요하면 스프린트 중 재회의 계획입니다.
상세 요약
Tutorial APK & Photos
팀은 튜토리얼용 디버그 APK와 갤러리 스타일의 새로운 사진 표시 방식을 검토했습니다. 디자이너(전형선)는 콜라주(사진이 많은 경우 자동 슬라이드되는 9-사진 그리드)를 구현하고 튜토리얼 흐름과 알림을 테스트했습니다; 그룹은 가시성 및 탐색에 대한 트레이드오프를 논의했습니다. 현재 상태는 디버그 빌드에서 작동하는 프로토타입이며 테스트가 완료되었고 소폭 조정이 계획되어 있습니다.
전형선 reports that the APK is uploaded and a collage-style gallery was implemented and tested in the debug app.
전형선 notes the gallery uses up to nine thumbnails and switches to slide behavior when photo count is large.
이동건 raises a visibility concern, saying the nine small thumbnails make photos too small to inspect before selection.
전형선 explains nine items were chosen to summarize a day at a glance and to avoid excessive scrolling.
이동건 requests the swipe behavior be constrained so the carousel does not loop, and asks for a clearer end-state indication.
Gallery Interaction Behavior
팀은 갤러리 상호작용에 대해 논쟁했습니다: 보이는 타일 수, 루핑 vs 경계 있는 캐러셀, 카드 스택 애니메이션 등. 이동건은 명확성을 높이기 위해 더 적은 개수의 보이는 항목과 비루핑 동작을 선호했고; 전형선은 요약 뷰를 유지하길 원하지만 원형 루프 애니메이션을 피하도록 변경하는 데 동의했습니다. 그들은 명확한 종료 인덱스를 가진 리스트 같은 횡스크롤(좌우 스와이프)을 채택하고 루핑 복귀 동작을 버그로 간주해 제거하기로 합의했습니다.
이동건 requests limiting visible items (suggesting four) to make photos larger and reduce confusion.
전형선 defends the nine-item view as a daily summary and notes prior experiments with 4-tile layouts.
이동건 identifies looping behavior (carousel wrapping) as a usability bug and requests the carousel stop at the last index.
전형선 agrees to remove the overlapping stacked-card return and implement left/right-only navigation with a non-wrapping end state.
Both agree the visual card overlap can remain but the motion should behave like a bounded list, and 전형선 will test and apply the animation changes.
Place-selection UI Options
핵심 논의는 이벤트 내 장소 표현을 위한 두 가지 디자인: 문장 내 인라인 포함(이안) 대 별도의 UI 요소/팝업(이하) 사이였습니다. 팀은 단계 축소와 마찰 감소 대 완전한 위치 기록 및 편집 가능성이라는 트레이드오프를 저울질했습니다. 그들은 이벤트당 하나의 장소 모델을 선호하며 제목에서 장소 이름을 제거하고 위치를 별도 섹션이나 부제목으로 처리하는 쪽으로 기울였습니다.
이동건 frames the main problem as difficulty for users to accurately choose a place, noting automated AI suggestions may be incorrect.
전형선 presents AI-generated mockups and suggests treating location as a separate component so textual descriptions can remain concise.
이동건 favors the 이안 approach (single place per event embedded in subtitle and not in title) because it reduces steps and keeps the title cleaner.
전형선 supports a single-place assumption and agrees removing place from titles is preferable while preserving a separate location field.
The team agrees to further refine whether place is embedded in sentence text or shown in a separate UI area, and to decide one approach before implementation.
AI Place Recommendation & Defaults
그들은 AI 기반 장소 제안 동작과 사용자 제어에 대해 논의했습니다. 이동건은 AI가 장소 후보를 순위화하고 앱은 상위 후보를 기본값으로 보여주되 사용자가 편집할 수 있는 능력을 보존할 것을 제안했습니다; 그는 필요한 사용자 상호작용을 최소화하되 편집 옵션을 유지하는 것을 강조했습니다. 현재 계획은 AI가 순위화된 후보를 제안하고 최상위 선택을 기본으로 제시하되 수동으로 변경 가능하게 하는 것입니다.
이동건 suggests AI should rank candidate locations and present the highest-probability candidate as the default selection.
이동건 emphasizes keeping user override capabilities so users can correct incorrect AI choices.
전형선 captured AI outputs and will test title/subtitle trade-offs to see how place names appear in generated text.
이동건 notes the app should avoid forcing users to edit many events and should minimize steps while still allowing corrections.
The team agrees the AI should reduce user friction by supplying good defaults but not remove the user's final control.
Granularity: Place vs Address vs Movement
언제 정확한 장소명이 중요한지, 언제는 대략적인 주소나 이동 라벨로 충분한지를 명확히 했습니다. 이동건은 이동 이벤트에는 상세한 장소명이 필요하지 않고 주소면 충분하다고 주장했고, 사용자가 시간을 보내는 이벤트에는 특정 장소 레이블을 유지해야 한다고 했습니다. 팀은 이동에는 주소를 사용하고, 의미 있는 정지형 이벤트에는 특정 장소명을 사용하는 쪽으로 기울였습니다.
이동건 suggests movement events only require coarse addresses, while stationary events need specific place names for clarity about activities.
전형선 agrees that separating a dedicated location section can preserve detail without cluttering the main text.
이동건 reiterates the product goal: keep defaults to minimize user editing but allow specific place naming for meaningful events.
전형선 highlights that isolating location as a component helps keep textual descriptions flexible while preserving structured place data.
The team decides to treat location differently by event type: address-only for movements and explicit place names for substantive events.
Editing, Deletion, and Data Safety
그룹은 제안된 장소 데이터를 사용자가 어떻게 편집하거나 삭제할지, 파괴적 행동에 대한 안전성에 관해 논의했습니다. 그들은 위치를 자유 텍스트로 삭제하는 대신 명시적 삭제(X) 컨트롤이 있는 컴포넌트로 취급할 것을 제안하고, 실수로 인한 데이터 손실을 방지하기 위해 잠금 또는 복구 흐름을 고려했습니다. 결정은 명시적 컴포넌트 수준 삭제 컨트롤을 제공하고 되돌리기/확인 흐름을 고려해 비가역적 손실을 피하는 것입니다.
이동건 warns that free-text deletion could accidentally remove important location context and asks for safe deletion patterns.
전형선 proposes componentized deletion (an explicit X) and raises concerns about irreversible deletion on mobile.
이동건 asks whether recovery or undo is necessary and suggests guarding critical deletions with confirmation or locks.
전형선 indicates deletions should behave differently from text edits to reduce accidental loss of structured location data.
The team agrees to implement explicit delete controls and consider an undo or confirmation flow for critical actions.
이동건 confirms that exiting an edit screen without pressing a separate save button should keep edits saved, and he prefers not forcing extra steps to recover from accidental deletion.
Next Steps & Implementation
그들은 선호 디자인과 후속 조치에 대해 합의하며 마무리했습니다: 갤러리 애니메이션을 경계 있는 리스트 동작으로 조정하고, 이벤트당 단일 장소 접근법(이안)을 확정하며 제목에서 장소를 제거하고 위치를 별도 섹션/부제목으로 처리하기, AI 프롬프트를 정교화해 순위화된 장소 후보를 제공하기, 안전한 편집/삭제 컨트롤을 추가하기. 전형선은 프로토타입을 업데이트하고 애니메이션을 테스트할 것이며; 팀은 코딩 전에 장소 UI 결정 최종화를 위해 다시 모이기로 했습니다.
전형선 will modify the gallery animation to remove looping and test left/right bounded swipe behavior.
The team decides to pursue the 이안 approach (single place per event and not in title) pending final UI detail decisions.
이동건 requests AI prompts be tuned so the top candidate is reliable and presented as the default while keeping user override.
The team agrees to implement explicit component deletion (X) and consider confirmation/undo behavior for location removal.
They plan to finalize place-UI decisions soon so engineering can start implementation, and 이동건 signals availability to work through the next day.
이동건 will update the team via Discord about his work and asks others to report progress as available, and both confirm aiming to complete outstanding items by Sunday.
