미팅 요약

메모
개요
Participants: 이동건 (lead/product developer), 정수현 (backend/product), 전형선 (mobile/Android). 회의는 예상치 못한 API 비용 급증 문제 해결, 서버·Android·AI의 조정된 프로덕션 릴리스 준비, 장소 제안 UX 개선, 애널리틱스와 알림 동작 개선, 광고 크리에이티브 최적화에 중점을 두었습니다.
주요 결과 및 결정 사항:
- 비용 급증의 근본 원인: 이동건은 자신의 테스트가 EMB 파일에 프로덕션 API 키를 남겨 반복적인 자동 호출을 초래한 것을 발견했습니다. 팀은 외부 키 유출이 없음을 확인하고 명시적 테스트 설정 강제 및 에이전트 반복 제한을 통해 재발을 방지하기로 결정했습니다(이동건 보고, 전형선·정수현 지지).
- 즉각적 완화 조치: 이동건은 로그를 추가 조사하고 청구 내역을 문서화하며 잔액을 충전하고 팀은 환불 및 부가가치세 처리 추적을 진행합니다(이동건·정수현 담당).
- 릴리스 계획: 팀은 서버 배포를 우선하고 앱 고장을 피하기 위해 모바일 및 AI를 동시에 업데이트하기로 우선순위를 정했습니다. 전형선은 Android 빌드를 Play 검토용으로 업로드하고 GA4 이벤트 테스트를 구현하며, 스토어 승인 후 강제 업데이트 타이밍을 조정할 예정입니다.
- 알림 동작: Android 알림은 OS의 배칭 때문에 몇 분 단위로 지연될 수 있습니다. 전형선이 조사하고 정밀한 타이밍이 불가능하면 선택 가능한 시간 범위를 좁히고 사용자-facing 공지를 추가하기로 했습니다(정수현 제안, 이동건·전형선 동의).
- UX 및 애널리틱스: 사진이 없을 때 장소 후보 정확도가 제한적입니다. 팀은 사용자 선택/확인용 UI를 추가하고 GA4 이벤트로 기능 사용과 롤아웃 영향을 측정할 계획입니다(이동건, 정수현, 전형선 작업).
- 광고: 비디오 크리에이티브가 이미지보다 성과가 낮아 팀은 이미지 기반 크리에이티브를 우선하고 예산/시간이 허락하면 짧은 편집본을 테스트할 예정입니다(이동건·정수현 논의).
약속 및 다음 단계:
- 이동건: 남아있는 로그 추적을 조사해 다른 이상 사용이 있는지 확인하고, $700을 충전하며 청구 내역을 문서화해 정산을 준비합니다; AI 관련 수정 완료 및 조정된 배포 준비.
- 전형선: GA4 이벤트 구현 마무리, 알림 타이밍 테스트, 디버그 및 릴리스 빌드를 Play Store에 업로드해 검토 시작, 릴리스 커뮤니케이션용 인앱 게시물/팝업 준비.
- 정수현: 기존/신규 사용자 대상 팝업 메시지 준비 및 애널리틱스와 릴리스 조정 지원.
모니터링할 우려 사항: 향후 우발적 프로덕션 호출을 방지하기 위한 청구 및 테스트 관행; 알림 타이밍 정밀도 및 사용자 경험; 사진·정확한 위치 데이터가 부족할 때 장소 제안 정확도 개선 필요. 팀은 내일까지 조정된 배포 준비를 목표로 남은 항목을 해결하고 롤아웃 중 긴밀히 소통하기로 했습니다.
상세 요약
Unexpected API cost spike
팀은 10월 31일과 11월 1일에 청구된 API 비용이 요청 수나 타임라인 수와 일치하지 않는 갑작스럽고 큰 증가를 관찰합니다. 처음에는 API 키 유출을 의심했으나 사용 패턴과 로그를 조사하여 근본 원인을 규명합니다. 문제는 나중에 내부 테스트에서 실수로 프로덕션 API 키를 사용한 것으로 추적되었고, 팀은 재발 방지를 위해 비용 통제 및 프로세스 변경을 계획합니다.
이동건 reports that API charges spiked to about $29 on Oct 31 and $14 on Nov 1 despite no obvious surge in timeline creation.
정수현 notes that aggregated costs in their monitoring (랭퓨즈/랭피즈) don't match the billed amount and says API key leakage is a likely explanation if internal counts don't add up.
이동건 says automated payments kept topping up the account and multiple small charges accumulated while they hadn't noticed.
이동건 concludes the cause was his own testing where he left the API key in an EMB file, and that agent tests repeatedly called the API causing the high charges.
전형선 and 정수현 react that the charge origin is fortunate (not an external leak) and recommend better explicit controls to prevent repeated autonomous calls.
Immediate mitigation actions
참석자들은 과도한 사용의 출처를 조사하고 추가적인 의도치 않은 청구를 중단하기로 결정합니다. 이동건은 로그를 추가로 확인하고 팀이 보호 장치를 구현하는 동안 일시적으로 청구 관리를 맡기로 합니다. 또한 회계 처리를 위해 청구 및 환불 내역을 문서화하기로 합의합니다.
이동건 says he will continue investigating the leak points and identify where calls are originating.
이동건 states he will top up $700 and document the $99 already charged so finance can reconcile costs and refunds.
정수현 clarifies that VAT and refund calculations follow the charged amount and that they will recover tax via standard processes.
전형선 and 정수현 advise limiting autonomous agent repetitions and making API usage explicit to reduce future cost exposure.
Production deployment sequencing
팀은 서버와 모바일 컴포넌트의 프로덕션 배포를 계획하며 서버 변경을 우선하고 모바일 릴리스를 조정해 앱 고장을 방지하기로 합니다. 서버, Android, AI 변경이 정렬되어야 하며 Android 릴리스는 검토를 위해 업로드된 후 승인이 나면 강제 업데이트를 적용할 수 있습니다.
이동건 states he intends to deploy the current AI changes to production today and asks about mobile status.
전형선 reports the debug Android build was uploaded before lunch and that GA4 event additions need final testing before release.
정수현 warns that releasing AI changes alone will break the app and says server, Android, and AI must be updated together.
전형선 says once the Play Store review passes they can enable the update and optionally force updates by changing the version code.
AI model usage and token patterns
팀은 모델별 토큰 사용량을 검사하고 두 모델(민과 루나)에서 유사한 패턴을 관찰하여 외부 남용보다는 내부 워크플로 사용을 시사합니다. 이는 높은 비용이 악의적 행위자보다는 자체 타임라인 생성 프로세스와 연관되어 있음을 의미합니다. 테스트 설정을 강화하고 에이전트 반복을 제한할 계획입니다.
이동건 shows model-level input token spikes for both 민 and 루나 on the same day, implying internal timeline generation caused increased usage.
이동건 argues that if a leak had occurred they'd expect calls to many different advanced models rather than the two used by the service.
정수현 confirms DB checks show no unusual user-driven request spikes and rules out multiple repeated requests from a single user.
이동건 commits to making agent test behavior explicit to avoid repetitive autonomous calls that drove costs.
Mobile analytics and GA4 events
모바일 작업에는 새로운 기능 사용을 캡처하기 위한 GA4 이벤트 추가와 온보딩 및 업데이트 수신률 측정이 포함됩니다. 전형선은 GA4 이벤트 구현과 로그 테스트를 완료해 릴리스를 진행할 예정입니다. 팀은 롤아웃 영향 모니터링을 위해 애널리틱스를 사용할 계획입니다.
전형선 says he needs to finish GA4 event implementation and testing so logs reliably appear before deployment.
정수현 explains the GA4 events capture is meant to gather metrics for new features and to support decision making on the release.
전형선 agrees to finalize analytics tests and to proceed with uploads for Play Store review in parallel.
Place candidate accuracy and UI
팀은 사진이 없을 때 특히 장소 후보 제안의 한계를 논의하고 사용자가 장소를 더 쉽게 선택하거나 확인할 수 있도록 디자인 조정을 고려합니다. 사진이 있으면 추론 정확도가 향상되지만 일반적인 장소명에 대해서는 여전히 모호성이 남습니다. 선택 UI를 강화하고 사용자 편집 가능한 입력을 우선시할 계획입니다.
정수현 notes many cases where the top-5 place candidates don't include a correct result, highlighting data coverage limits.
전형선 says photo-backed suggestions perform better and suggests adding a verification step when photos exist to improve accuracy.
이동건 says he'll record user selections and prioritize that data to improve candidate selection and will complete the related update by the end of the day.
정수현 and 전형선 agree some limitations are unavoidable when location information or names are ambiguous.
Ad performance and creative choices
팀은 최근 광고 성과를 검토하고 비디오 크리에이티브가 이미지 광고보다 성과가 나쁘다는 것을 발견하여 캠페인에서 AI 비디오를 제거하는 방안을 논의합니다. 대안을 테스트하는 것을 고려하지만 테스트에는 광고 예산이 필요하므로 팀은 이미지 크리에이티브를 우선하고 시간이 허락하면 짧은 편집본을 실험하기로 결정합니다.
이동건 reports that video ads underperform compared with image ads and that CTR dropped though remained stable enough.
정수현 recommends removing the AI video and running a simple app-intro image creative instead.
이동건 says testing a new creative requires budget and time and that he remains unsure if replacing video yields sufficient uplift.
전형선 will capture and share acquisition/visibility screenshots to help evaluate ad metrics.
Notification timing and UX
사용자들이 설정한 시간보다 몇 분 늦게 알림을 받는 문제가 있어 팀은 Android 예약과 OS 제약을 조사합니다. 편차를 줄이기 위해 선택 가능한 시간을 제한하는 방안을 고려하고 UI/커뮤니케이션 변경으로 알림 동작을 사용자에게 알릴 계획입니다. 팝업 및 온보딩 업데이트가 제안되었습니다.
정수현 reports users noticed the reminder time change after moving scheduling to local handling and asks whether the timing difference is intentional.
전형선 explains Android policies and system batching can cause imprecise notifications to save system resources and agrees to investigate further.
이동건 insists that selected times must be respected and asks for a fix so notifications do not arrive at differing minutes.
정수현 suggests narrowing selectable time ranges (e.g., on-the-hour or 30-minute increments) and using popups or onboarding to explain the behavior to users.
Release communication and onboarding
팀은 기존 사용자에게는 팝업을, 신규 사용자에게는 온보딩을 통해 변경 사항(알림, 장소 선택, 크레딧)을 전달하기로 결정합니다. Play 스토어 노트에만 의존하지 않고 앱 내 공지와 간결한 업데이트 게시를 계획합니다. 팝업 및 업데이트 콘텐츠 준비는 Android 릴리스 전에 할당됩니다.
정수현 proposes using a popup for existing users and onboarding flows for new users to convey the notification and new-place-selection changes.
전형선 agrees to prepare a short in-app post and to include change notes when submitting the Play Store release.
정수현 offers to prepare targeted popup UI so specific users (e.g., new vs existing) can see appropriate messaging before the next release.
Final tasks and timeline
팀은 즉각적인 다음 단계에 합의합니다: 서버 머지 및 배포, Android GA4 및 알림 동작 최종화, 팝업/업데이트 공지 준비, 그리고 충돌을 피하기 위해 AI와 모바일을 동시에 릴리스 조정. 이 항목들을 내일까지 완료하고 롤아웃 중 긴밀히 소통하기로 약속합니다.
이동건 asks the team to prioritize server deployment first and then coordinate mobile and AI releases to avoid app breakage.
전형선 commits to uploading the debug build and starting Play Store review, and to check notification accuracy and GA4 event tests.
정수현 will prepare the popup messaging and coordinate the release notes and targeted popup visibility for users.
The group agrees the target is to finish tasks and be ready for a coordinated rollout by tomorrow.

- 이동건이 계정에 $700을 추가 충전하고 지불 및 부가세 내역을 문서화하여 정수현이 환불 기대치를 조정할 수 있게 할 것.
- 이동건이 기술 작업의 최종 보고서 템플릿/설정을 준비하여 이후 개발 작업 시 다른 사람들이 무엇을 기재해야 할지 알 수 있게 할 것.
- 이동건이 오늘 AI 관련 코드 업데이트를 완료하고 프로덕션에 배포할 것, place-candidate 변경 사항을 포함시키고 모바일 및 서버 릴리스와 타이밍을 조율할 것.
- 정수현이 서버 머지 사항을 검토하고 Android 릴리스 직전에 프로젝션 검토를 바로 올릴 것.
- 이동건이 EMB 파일에 API 키가 저장된 위치를 조사하고 찾아서 제거하거나 보안을 강화할 것; 반복적인 API 사용을 제한하기 위해 자동화된 테스트 에이전트 호출을 계속 줄일 것.
- 전형선이 Android 디버그 빌드를 실행하고 릴리스를 심사 제출한 후(심사), 스토어 심사가 승인되면 이동건에게 알려 강제 업데이트를 진행할 수 있게 할 것.
