## 베타테스터 모집

가장 중요하고 가장 오래 걸린다. 다른 것보다 먼저 시작한다.

### 채널 (순서대로)

1. **지인** - 1순위. 직접 연락. 여기서 절반 이상 채우는 게 현실적이다.
2. **SW마에스트로 17기 연수생** - 내부 채널로 공지. 이미 접점이 있어 전환율이 높다.
3. **개발자 커뮤니티** - 앱이라 채널 선택이 애매한 부분. 후보를 정해야 한다.

### 앱 소개 페이지

모집 글을 어디에 올리든 링크 하나로 끝나는 소개 페이지가 필요하다. 이게 없으면 어느 채널도 진행이 안 된다. 가장 먼저 만든다.

- [ ] 페이지 형태 결정 (Notion 공개 페이지가 가장 빠름 / 별도 랜딩 페이지)
- [ ] 내용: 앱이 뭘 해주는지 한 문단, 스크린샷 몇 장, 테스트 기간, 필요한 권한과 사용 데이터, 보상, 설치 방법, 신청 폼 링크
- [ ] 신청 폼 (Google Form): 이름/연락처, Android 기기·버전, 참여 가능 여부

### 보상

- [ ] 무엇을 줄지 확정한다

후보:
- 5개 이상 작성자 전원에게 커피 기프티콘 (가장 단순, 예산 예측 가능)
- 5개 이상 작성자 전원 소액 + 인터뷰 참여자 추가 지급 (인터뷰 확보에 유리)
- 추첨 방식 (예산은 적게 들지만 참여 동기가 약함)

**결정 필요:** 예산 총액, 지급 기준(5개 작성 확인 방법), 지급 시점(종료 후 일괄).

### 체크리스트

- [ ] 앱 소개 페이지 완성
- [ ] 신청 폼 완성
- [ ] 보상 확정
- [ ] 지인 대상 모집 시작
- [ ] SW마에스트로 17기 공지
- [ ] 개발자 커뮤니티 채널 확정 후 게시
- [ ] 참여자 명단과 기기 확인 (약 20명)
- [ ] 설치 안내와 문의 창구 전달
- [ ] 종료 설문 / 인터뷰 질문 준비

## MVP 기능 완성

로그인부터 타임라인 생성·편집·저장까지 끊김 없이 되어야 한다. 여기까지가 베타의 최소 조건이다.

- [ ] 로그인
- [ ] 권한 설정 및 데이터 수집
- [ ] AI 타임라인 생성
- [ ] 생성 결과 확인
- [ ] 이벤트 수정 / 삭제
- [ ] 메모 추가
- [ ] 저장·확정 (일간 회고 완료)
- [ ] 월별 기록 조회
- [ ] 실제 기기에서 위 흐름 처음부터 끝까지 1회 통과

새 기능은 베타 이후로 미룬다. 목표 추적, AI Chat, AgentCore 전환은 이번 범위가 아니다.

## 로그 수집 체계

중간보고서에서 정한 앱 내부 KPI가 **전부** 실제로 수집돼야 한다. 하나라도 빠지면 베타 결과를 보고서에 못 쓴다.

- [ ] 권한 동의율
- [ ] 타임라인 완료율
- [ ] 이벤트 수정률
- [ ] 이벤트 삭제율
- [ ] 메모 추가율
- [ ] 평균 메모 작성 수
- [ ] D1 / D7 / D30 리텐션

수집 확인:

- [ ] 각 KPI를 계산하는 데 필요한 이벤트가 앱에서 실제로 발생하는지
- [ ] 테스트 계정으로 전체 흐름을 한 번 돌고 GA4에 반영되는지
- [ ] 사용자별로 묶여서 리텐션 계산이 가능한지
- [ ] 이벤트에 메모 본문·사진·위치·타임라인 원문이 들어가지 않는지
- [ ] 결과를 볼 집계표 또는 대시보드

## 알림 발송 설계

테스터에게 알려주기 위한 알림. 지금은 설계부터 필요하다.

정리할 것:

- [ ] 어떤 알림을 보낼 것인가
  - 타임라인 생성 완료 (기능 알림, 이미 있음)
  - 오늘 타임라인 만들어 보라는 리마인드
  - 베타 공지 (시작, 종료 임박, 설문 요청)
- [ ] 발송 시각과 빈도 (하루 1회 이상은 이탈 위험)
- [ ] 발송 수단: 앱 푸시(Firebase) / 별도 공지 채널(오픈채팅·메일) 구분
- [ ] 알림 수신 여부와 클릭을 로그로 남길 것인가

**결정 필요:** 리마인드를 푸시로 보낼지, 아니면 베타 기간엔 단톡방 공지로 대체할지.

## AI / 모바일 / 서버 각자 할 일

### AI - Nova 2 Lite 전환과 비용

이미 만든 평가 시스템을 그대로 쓴다. 새 평가 도구를 만들지 않는다.

- [ ] 정량 메트릭을 fix한다 (더 이상 바꾸지 않을 최종 목록으로 확정)
  - source 충실도 (hallucinated rawId)
  - structured output 실패율 / fallback 횟수
  - Repair 발생 횟수
  - latency
  - token, 실제 비용
- [ ] 고정 조건으로 평가를 돌린다 (같은 commit, prompt version, fixture, temperature)
- [ ] GPT-5.4 mini(현행) vs Nova 2 Lite 결과를 같은 표로 비교
- [ ] Nova 2 Lite로 전환할지 결정하고, 전환하면 prompt를 Nova 기준으로 재조정
- [ ] 남은 비용 절감 지점 정리 (이미지 bytes, 호출 횟수, Repair 상한 등)

베타 전에 모델을 확정해야 한다. 베타 중간에 모델을 바꾸면 수집한 지표를 비교할 수 없다.

**결정 필요:** 어느 수준이면 Nova 2 Lite로 넘어갈 것인가? (예: 품질 동등 + 비용 X% 절감)
